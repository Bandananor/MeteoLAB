# StormLab (MeteoLAB): подробный обзор проекта

Документ описывает, что такое StormLab, как устроен код, как он работает на каждом шаге
расчёта и отрисовки, и как проект развивался по истории коммитов. Он дополняет
[README](../README.md) (для пользователя) и [ROADMAP](../ROADMAP.md) (планы).

---

## 1. Что это за проект

**StormLab** — браузерная 3D-лаборатория атмосферной конвекции. Пользователь задаёт
вертикальный профиль атмосферы: температуру и её градиенты по слоям, влажность, ветер
на высотах 0/3/6/10 км, тип поверхности, время суток. Упрощённая численная модель в
реальном времени считает движение воздуха, тепла и влаги. Из этого расчёта «сами»
вырастают кучевые облака, одиночные грозы, мультиячейки, суперячейки с мезоциклоном,
микропорывы.

Ключевые свойства:

- **Нет сервера.** Всё считается в браузере на CPU (TypeScript), рисуется через WebGL 2
  (Three.js). Сборка — Vite.
- **Физическая модель, а не анимация.** Облака получаются из уравнений (перенос,
  плавучесть, конденсация, проекция давления), а не рисуются по сценарию.
- **Инструменты синоптика.** Аэрологическая диаграмма с CAPE/CIN, годограф, уровни
  LCL/LFC/EL/0 °C, спиральность восходящего потока (UH), классификация режима конвекции,
  текстовое объяснение происходящего.
- **Весь интерфейс на русском языке.**

### Технологический стек

| Что | Чем |
|---|---|
| Язык | TypeScript ~6.0 (strict, `noUnusedLocals`, `erasableSyntaxOnly`) |
| Сборка / dev-сервер | Vite 8 |
| 3D | Three.js 0.185 (`WebGLRenderer`, `OrbitControls`, `ShaderMaterial`, `Data3DTexture`) |
| Шейдеры | GLSL (WebGL 2: `sampler3D`) |
| Графики справа | Canvas 2D |
| Лицензия | MIT |

Команды: `npm run dev`, `npm run build` (`tsc && vite build`), `npm run preview`.
Автотестов в репозитории нет (см. раздел 7).

## 2. Структура репозитория

```
index.html            — пустая страница с <div id="app"> и подключением src/main.ts
src/main.ts           — интерфейс: панели, ползунки, сценарии, вкладки, диаграммы (≈270 строк)
src/simulator3d.ts    — класс Atmosphere: физическая модель + 3D-сцена (≈300 строк)
src/volumeShaders.ts  — GLSL: объёмные облака, тени, срезы полей, снег/дождь (≈275 строк)
src/style.css         — стили (сжатые в несколько очень длинных строк)
public/               — favicon и иконки
README.md             — описание для пользователя
ROADMAP.md            — план «StormLab 2.0»
LICENSE               — MIT
```

Код написан в очень плотном стиле: многие методы — одна длинная строка, короткие имена
переменных. Это делает файлы компактными, но читать их удобнее с переносом строк.

## 4. Физическая модель (`src/simulator3d.ts`)

### 4.1. Сетка и константы

- Область **48 × 36 × 15 км**, сетка **NX × NY × NZ = 40 × 32 × 24** (30 720 ячеек).
- Шаг: Δx = 1,2 км, Δy ≈ 1,13 км, Δz ≈ 0,65 км; шаг по времени **Δt = 1 с**.
- Боковые границы **периодические**: что уходит на восток, возвращается с запада.
  Соседей ищут через заранее посчитанные таблицы `XP/XM/YP/YM`.
- Индексация: `i = x + NX·(y + NY·z)`; один горизонтальный слой — `LAYER = NX·NY`.
- Константы: g, cp, Lv, κ = R/cp, Rd, ε = 0,622, угловая скорость Земли Ω.

### 4.2. Прогностические поля

| Поле | Смысл |
|---|---|
| `u, v, w` | компоненты ветра, м/с |
| `theta` | потенциальная температура θ, K |
| `q` | удельная влажность (пар), кг/кг |
| `cloud` | облачная вода, кг/кг |
| `rain` | дождевая вода, кг/кг |
| `cold` | «индикатор» холодного бассейна (cold pool): накопленное охлаждение, K |
| `pressure` | возмущение давления (решение уравнения Пуассона) |

Вспомогательные массивы: `divergence`, `scratch`, `surfacePattern` (случайная неоднородность
нагрева поверхности), `backtrace` (кэш полулагранжевых точек).

### 4.3. Окружающая среда (фоновое состояние)

Профили строятся из `SimConfig`:

- **Температура** кусочно-линейная: градиент `lapseLow` в слое 0–3 км, `lapseMid` в 3–8 км,
  `lapseUpper` до тропопаузы, выше — потепление `stratoWarming` (стратосфера).
- **Давление** — барометрическая формула `p = 101325·exp(−z/8000)`.
- **θ** из T и p; **насыщение** по формуле Магнуса (`qsatP`, ограничено 45 г/кг).
- **Влажность** — относительная влажность, интерполированная между уровнями
  «у земли / 1,5 км / 5 км / тропопауза», умноженная на q_sat.
- **Ветер** — скорость и направление, интерполированные между 0, 3, 6, 10 км; перевод
  метеорологического направления в (u, v): `a = (270 − dir)°`.

`computeEnv()` один раз табулирует всё это на каждом уровне модели (p, Exner, θ, q, u, v):
окружение меняется только при перезапуске, а в цикле шага формулы больше не считаются.

### 4.4. Инициализация

`initialize()`:
1. строит `surfacePattern` — сглаженное случайное блуждание (seed через `mulberry32`),
   которое делает нагрев поверхности пятнистым;
2. заполняет поля фоновыми значениями + крошечный шум θ;
3. вбрасывает **два тёплых влажных пузыря** (`injectBubble`) — в точках (38 %, 45 %) и
   (61 %, 57 %) области, второй слабее (0,72). Пузырь — гауссиана радиусом ~4,2 км по
   горизонтали и ~1,8 км по вертикали: +3,2 K к θ, +3 г/кг к q, +1,1 м/с к w (× сила).

Двойной клик по земле (`perturb`) бросает луч из камеры, находит точку на земле и
вбрасывает туда такой же пузырь силой 1,25.

### 4.5. Один шаг модели — `step(dt)`

`advance(realDt)` копит время `realDt × speed` и делает до 12 шагов по 1 с за кадр.
Каждый шаг:

1. **Перенос дождя** отдельной полулагранжевой адвекцией с падением со скоростью
   `RAIN_FALL = 7 м/с` (к w добавляется −7 м/с) и слабым затуханием.
2. **Полулагранжев перенос остальных полей.** `computeBacktrace` один раз на шаг
   вычисляет для каждой ячейки точку отправления `x − u·dt` и 8 угловых индексов +
   3 веса трилинейной интерполяции. `advectBacktrace` применяет этот кэш к u, v, w,
   θ, q, cloud, cold. Все поля переносятся **одной и той же скоростью до шага**
   (раньше каждое следующее поле видело уже перенесённый ветер).
3. **Цикл по всем ячейкам** (физика «в точке»):
   - **Конденсация**: если q > q_sat, пар переходит в облако (релаксация 0,32/с),
     θ растёт на `Lv/cp/Π · Δq` (скрытая теплота).
   - **Испарение облака** в ненасыщенном воздухе (масштаб — «вовлечение»), охлаждение
     и частичный вклад в `cold`.
   - **Автоконверсия** облако → дождь выше порога 0,9 г/кг (масштаб — «эффективность
     осадков»).
   - **Испарение дождя** под облаком → охлаждение, умноженное на «силу cold pool»,
     целиком идёт в `cold`. Это источник нисходящих потоков и порывов.
   - **Плавучесть**: `B = θ'/θ_env + 0,61·q' − 1,8·cloud − 2,5·rain` (виртуальный
     эффект пара и нагрузка конденсатом), `w += g·B·dt`.
   - **Кориолис и затухание — только для отклонения** от фонового ветра:
     `du = (u − u_env)·0,9999`, затем поворот на `f·dt`. Так фоновый сдвиг ветра не
     размывается (исправлено в коммите `3dba857`, раньше сдвиг терялся на ~30 % за час).
   - **Поверхностные потоки** в двух нижних уровнях: солнечный нагрев
     `insolation × (1 − альбедо) × доля явного тепла / инерция` и испарение
     (× влажность почвы). Параметры поверхности: трава / сухая почва / вода / город.
     Инсоляция — синусоида от 6:00 до 18:00 с максимумом `solarMax`.
   - **Динамика cold pool**: на краю холодного бассейна (горизонтальный градиент `cold`)
     воздух выталкивается вверх — это gust front, триггер новых ячеек; в центре
     холодного бассейна у земли — дополнительное опускание.
   - **Микропорыв**: если у земли w < −5 м/с при заметном дожде, считается «удар»,
     ветер растекается радиально, растёт `cold`, обновляется глобальный показатель
     `microburstOutflow`.
   - **Субсеточное перемешивание** θ и q с 4 соседями (ползунок «турбулентность»).
   - **Губка** над тропопаузой (≥ 13 км): w гасится, u, v, θ тянутся к фону, чтобы волны
     не отражались от верхней крышки.
4. **Проекция давления** `project(dt, 16)`: считается дивергенция, 16 итераций
   **SOR** (ω = 1,7) решают уравнение Пуассона для давления с тёплым стартом от
   прошлого шага; граничные условия — `dp/dz = 0` у земли, `p = 0` наверху, по бокам
   периодичность. Затем из скорости вычитается градиент давления (поле становится
   почти бездивергентным), скорости ограничиваются ±85 м/с по горизонтали и ±60 м/с по
   вертикали. Проекция приближённая: 16 итераций не убирают дивергенцию полностью.
5. **Граничные условия по вертикали**: w = 0 у земли и наверху, приземное трение
   `u, v *= 0,94` (роадмап предлагает заменить это нормальным приземным слоем).
6. **Частицы** (если включены «Потоки» или «Снег и дождь») и **детекция вращения**.

### 4.6. Детекция мезоциклона (`updateRotation`)

Для каждой колонки считается **спиральность восходящего потока**
`UH = Σ w·ζ·Δz` в слое 2–5 км, где `ζ = ∂v/∂x − ∂u/∂y` — вертикальная завихренность.
Берутся максимум (циклоническое вращение) и минимум (антициклоническое).

- UH ≥ 100 м²/с² — «в потоке появилось вращение» (серое кольцо над ядром);
- UH ≥ 150 м²/с² **непрерывно 10 минут** модельного времени — **мезоциклон**:
  режим меняется на «Суперячейка с мезоциклоном», кольцо становится янтарным;
- сильный антициклонический UH — признак расщепления на правую и левую ячейки.

Пороги откалиброваны под грубую диффузную сетку ~1 км (в оперативных моделях 3 км
используют ~75 м²/с²).

### 4.7. Зондирование частицы (`computeParcel`)

Считается один раз при создании модели (окружение не меняется до перезапуска):

- частица стартует от земли с T + 0,5 °C и приземной влажностью;
- поднимается шагами 100 м: сухоадиабатически (9,8 K/км) до насыщения, затем по
  влажной адиабате (формула с учётом Lv·q_sat);
- на каждом шаге подмешивается окружающий воздух (вовлечение);
- по виртуальной температуре находятся **LCL**, **LFC**, **EL**, интегрируются **CAPE**
  (между LFC и EL) и **CIN** (ниже LFC);
- дополнительно: профиль ветра 0–10 км каждые 250 м (для годографа) и **уровень 0 °C**.

### 4.8. Диагностика и классификация (`diagnostics`)

Каждый кадр по всей сетке ищутся макс. updraft/downdraft, вершина облака (cloud > 0,07 г/кг),
вершина термика (w > 0,6 м/с), макс. облачная вода, макс. cold pool ниже 1,5 км,
«интенсивность осадков» (прокси). `countCores()` считает **ядра восходящих потоков**:
колонки с w > 2 м/с и облаком на высотах ~2–7 км, связанные компоненты которых находятся
заливкой (flood fill) с учётом периодичности.

Режим выбирается правилами:

| Условие | Режим |
|---|---|
| cold pool > 7 K и updraft < 2 м/с | Outflow-dominant |
| ≥ 3 ядер | 3D-мультиячейка |
| 2 ядра | Две взаимодействующие ячейки |
| 1 ядро и сдвиг 0–6 км > 18 м/с | Наклонённая организованная ячейка |
| 1 ядро | Одиночная 3D-ячейка |
| облако выше 1 км | Развивающийся 3D cumulus |
| иначе | Термики пограничного слоя |
| мезоциклон ≥ 10 мин | **Суперячейка с мезоциклоном** (перекрывает всё) |

Блок «Логика» собирает объяснение из фраз в зависимости от того, до какого уровня
(LCL / LFC / EL) дошла вершина облака, есть ли cold pool, микропорыв, вращение,
расщепление.

## 5. Отрисовка

### 5.1. Сцена (Three.js)

- 1 единица сцены = 1 км. Оси: +X — восток, +Y — вверх, **−Z — север** (в коммите
  `5bf46fa` исправили зеркальную сцену, где север был на +Z).
- Земля — `MeshStandardMaterial` цвета поверхности; сетка, каркас области,
  полупрозрачные плоскости уровней LCL / LFC / EL и уровня 0 °C.
- Камера — `OrbitControls` с демпфированием, камера не опускается под землю.
- Тонмаппинг ACES, туман `FogExp2`.
- **Солнце** (`sunDirection`) движется по местному времени и широте (равноденствие:
  восход в 6:00, закат в 18:00, в согласии с инсоляцией). У низкого солнца свет тёплый,
  интенсивность и цвета неба плавно меняются.

### 5.2. Объёмные облака (`volumeFragment`)

Каждый кадр `updateVolume()` упаковывает `cloud` и `rain` в двухканальную 3D-текстуру
(`RG`, 8 бит). Куб области рисуется задними гранями, фрагментный шейдер делает
**raymarching**:

- до 96 шагов вдоль луча, дрожание стартовой точки (против полос);
- плотность облака «разъедается» fbm-шумом: сетка ~1 км, а шум даёт кучевую фактуру
  мельче сетки; шум медленно дрейфует со временем;
- **закон Бугера–Ламберта** для поглощения, **5 шагов к солнцу** для самозатенения;
- фазовая функция — смесь двух **Хеньи–Гринстейна** (вперёд и назад), **powder effect**
  (тёмные края плотных облаков), высотный градиент окружающего света;
- дождь — серые полосы с собственным цветом;
- туман по взвешенной глубине, тонмаппинг и premultiplied alpha.

### 5.3. Тени облаков на земле (`groundShadowPars`)

Шейдер земли патчится через `onBeforeCompile`: для каждой точки земли 24 выборки той же
3D-текстуры по направлению к солнцу дают оптическую толщину. Ослабляется **только прямой**
солнечный свет, рассеянный свет неба остаётся, поэтому тень не чёрная.

### 5.4. Поля: срезы и объём

Вкладки «Вертикальные потоки», «Температура», «Влажность», «Завихренность», «Вращение (UH)»,
«Cold pool». Для выбранного поля `updateFieldTexture` пишет нормированные значения в
одноканальную 3D-текстуру, строит палитру (для знакопеременных полей — расходящаяся
синяя–красная). Дальше:

- **два подвижных среза** (горизонтальный по высоте и вертикальный север–юг):
  цветовая шкала, изолинии каждые 10 % диапазона, чёрная линия нуля
  (`sliceFragment`, сглаживание через `fwidth`);
- **объём сильных отклонений** (`fieldVolumeFragment`): светятся только значения далеко от
  нейтрального, порог задан для каждого поля;
- облака при этом становятся полупрозрачными (22 %), лучи объёмов обрываются на срезах.

### 5.5. Частицы

- **«Потоки»**: 10 000 частиц, переносимых модельным ветром (трилинейная интерполяция),
  цвет по w: оранжевые вверх, синие вниз; плюс редкие стрелки-векторы.
- **«Снег и дождь»**: до 8 000 частиц рождаются там, где в модели есть дождь, падают
  со скоростью от 2 м/с (снег) до 7 м/с (дождь), тают в слое 600 м под уровнем 0 °C
  (снежинка с шестью лучами → вытянутая капля в шейдере `precip*`) и исчезают там, где
  дождь в модели испарился. Льда в модели нет, так что фаза чисто визуальная: она
  определяется высотой относительно уровня 0 °C среды.

## 6. Интерфейс (`src/main.ts`)

- **Разметка** генерируется шаблонными строками; функция `slider()` создаёт ползунок с
  подписью и форматированием.
- **`defaults`** — исходные параметры («Летний день»). **7 сценариев** — небольшие
  наборы переопределений поверх `defaults`: «Летний день», «Мощная гроза», «Сухой воздух»,
  «Сдвиг ветра», «Микропорыв», «Суперячейка» (откалибрована так, чтобы мезоциклон
  появлялся к ~40-й минуте), «Жаркий город». Скорость времени при смене сценария
  сохраняется.
- **Живые и перезапускающие параметры.** Объект `config` передаётся в `Atmosphere`
  **по ссылке**, поэтому ползунки меняют модель на лету. Параметры из `resetKeys`
  (профили T, RH, ветра, широта, seed, сила пузыря, поверхность) меняют окружение и по
  отпусканию ползунка пересоздают модель (`recreate()`); состояние вида (`view`:
  вкладка, срезы, переключатели) переносится в новую модель.
- **Главный цикл** `frame()`: `advance` (если не пауза) → `render` → `diagnostics` →
  обновление цифр; раз в 20 кадров перерисовываются **аэрологическая диаграмма**
  (кривые среды, точки росы и частицы, заливка CAPE/CIN, линия 0 °C, подписи уровней)
  и **годограф** (цвет по слоям 0–3/3–6/6–10 км, сдвиг 0–6 км с подсказкой:
  < 10 м/с — одиночные ячейки, < 20 — мультиячейки, ≥ 20 — возможны суперячейки).

## 8. Замечания по текущему коду

Что стоит знать тому, кто продолжит разработку:

- **Весь расчёт идёт в главном потоке.** При ускорении 30× это ~30 шагов по ~23 мс на
  секунду реального времени, и интерфейс начинает подтормаживать. Отсюда приоритет
  Web Worker в роадмапе.
- **`diagnostics()` вызывается каждый кадр** и каждый раз проходит всю сетку и ищет
  ядра заливкой. Результат меняется только после шага модели, так что его можно
  кэшировать (или считать реже).
- **Зондирование не пересчитывается при «живых» ползунках.** `computeParcel` использует
  `entrainment`, но этот ползунок не входит в `resetKeys`: он сразу влияет на испарение
  облака в модели, а CAPE/CIN/LFC на диаграмме остаются старыми до перезапуска.
- **`updateFieldTexture` пересчитывает `pressureAt`/`thetaEnv`** на каждом уровне, хотя
  эти значения уже табулированы в `this.env`.
- **Частицы осадков используют `Math.random()`**, а не seed-генератор модели. Это только
  визуализация, но повтор эксперимента с тем же seed покажет другие частицы.
- **Периодические границы**: гроза, дошедшая до края, входит с другой стороны и может
  попасть в собственный холодный бассейн.
- **Нет автотестов.** Проверочный стенд из коммита `3dba857` в репозиторий не попал.
- **Стиль кода** сжатый (длинные строки, однобуквенные имена). Для совместной работы
  стоит подключить форматтер (например, Prettier) и хотя бы разбить `step()` на
  именованные подшаги (микрофизика, поверхность, cold pool, губка).
- При сборке Vite предупреждает о чанке > 500 кБ (в основном Three.js). Для локального
  приложения это не критично.

## 9. Краткий итог

StormLab — компактный (~850 строк своего кода) и при этом содержательный проект:
настоящая, хотя и сильно упрощённая, негидростатическая модель облачной конвекции
с полулагранжевым переносом, проекцией давления, тёплой микрофизикой и динамикой cold pool,
которая считается в реальном времени в браузере. Её дополняют качественная объёмная
визуализация (raymarching с физическим освещением, тени, срезы полей) и набор
синоптических диагностик вплоть до детекции мезоциклона. Проект создан за один вечер,
история показывает сначала рост возможностей, затем исправление физики и ускорение
ядра, а роадмап задаёт понятный путь к версии 2.0.
