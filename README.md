# StormLab

Идеализированная облакоразрешающая модель глубокой конвекции, которая считается в браузере
в реальном времени, с 3D-визуализацией и диагностикой в духе оперативной синоптики.
Задаётся зондирование (профили температуры, влажности и ветра) и поверхность, дальше
модель интегрирует уравнения движения, термодинамики и тёплой микрофизики на сетке ~1 км.

**Статус.** Версия 1.x работает; идёт переход к 2.0, цель которого — чтобы числам модели
можно было доверять (план — [`roadmap.markdown`](roadmap.markdown)). Часть физики пока
упрощена или подогнана; всё известное перечислено в разделе
[«Известные ограничения»](#известные-ограничения) с замерами.

## Быстрый старт

Нужны [Node.js](https://nodejs.org/) 20+ и браузер с WebGL 2.

```bash
git clone https://github.com/Bandananor/MeteoLAB.git
cd MeteoLAB
npm install
npm run dev      # приложение: http://localhost:5173
npm test         # тесты расчётного ядра (Node, без браузера)
npm run build    # проверка типов и сборка в dist/
```

## Постановка модели

### Область и сетка

| | |
|---|---|
| Область | 48 × 36 × 18,9 км, периодическая по горизонтали |
| Сетка | 40 × 32 × 30 узлов: Δx = 1,2 км, Δy = 1,125 км, Δz ≈ 0,652 км (равномерная) |
| Границы по вертикали | земля и верх — непроницаемые стенки (w = 0); губка Рэлея выше max(z_тп + 2,5 км, 14 км) |
| Шаг по времени | Δt = 1 с |
| Размеры | параметры ядра (`createGrid`), в интерфейсе пока фиксированы |

### Переменные и базовое состояние

Прогностические поля в узлах сетки: u, v, w; потенциальная температура θ; массовые доли
пара q_v, облачной воды q_c, дождя q_r; индикатор холодного купола (cold pool).

Базовое состояние горизонтально однородно и задаётся ползунками:
T(z) — кусочно-линейная с градиентами в слоях 0–3, 3–8 км и 8 км–тропопауза и инверсией
выше; относительная влажность — кусочно-линейная по узлам 0; 1,5; 5 км и тропопауза;
ветер — скорость и направление в узлах 0, 3, 6 и 10 км с линейной интерполяцией.
Давление интегрируется гидростатически по этому профилю: dp/dz = −p·g/(R_d·T_v),
p₀ = 1013,25 гПа. Относительная влажность понимается как отношение массовых долей
(r = RH·r_s, соглашение ВМО).

### Динамика

- Неупругое (anelastic) приближение: ∇·(ρ₀(z)**u**) = 0, ρ₀ — плотность гидростатического
  базового состояния (падает примерно в 8 раз к 19 км).
- Плавучесть B = g·[(θ_v − θ_v0)/θ_v0 − q_c − q_r], θ_v = θ·(1 + 0,61·q_v): конденсат
  утяжеляет воздух своей массой.
- Сила Кориолиса на f-плоскости, действует на отклонение ветра от фонового
  (фоновый ветер считается геострофическим).
- Горизонтальное перемешивание θ и q_v (без перемешивания импульса и без вертикального).
- Трение у земли — умножение ветра нижнего уровня на 0,94 за шаг (временно, до приземного слоя).
- Параметризованы: подъём воздуха на краю холодного купола и радиальный отток микропорыва.

### Численные методы

- **Перенос** — полулагранжев: точка отправления первого порядка по скорости в узле,
  трилинейная интерполяция; одна таблица точек отправления на шаг для всех полей.
- **Проекция давления** — точная и согласованная. Скорости хранятся в узлах, давление —
  в центрах «двойственных» ячеек между узлами. Дивергенция ячейки D — поток через её
  грани по восьми углам (именно её видит трилинейный перенос), градиент G = −M⁻¹Dᵀ
  (половинный вес узлов на стенках); условие — D(ρ₀**u**) = 0, так что D·ρ₀·G — согласованный
  лапласиан с весом плотности (поправка — градиент p′/ρ₀). Плотность зависит только от z, поэтому он
  диагонализуется двумерным ДПФ по x, y; для каждой волны решается трёхдиагональная
  система по z. Остаточная дивергенция после проекции ~10⁻¹¹ с⁻¹ (предел float32).
  Код: [`src/core/pressure.ts`](src/core/pressure.ts).
- **Фиксатор массы воды.** Трилинейный полулагранжев перенос не консервативен
  (без поправки гроза создаёт ~7,5 % воды в час даже на строго бездивергентной скорости).
  После переноса массы q_v, q_c, q_r (вес ρ₀) восстанавливаются (для дождя — за вычетом
  выпавшего на землю), поправка распределяется пропорционально локальному изменению поля.
  Временная мера до консервативной схемы переноса в форме потоков.

### Микрофизика (тёплая, объёмная)

- Насыщающая коррекция за один шаг: Δq = (q − q_s)/(1 + L²·q_s/(c_p·R_v·T²)), два шага
  Ньютона; избыток пара конденсируется, облако в ненасыщенном воздухе испаряется до насыщения.
- Схема Кесслера (как в Klemp & Wilhelmson 1978 и CM1): автоконверсия 0,001·(q_c − 1 г/кг) с⁻¹,
  аккреция 2,2·q_c·q_r^0,875 с⁻¹.
- Скорость падения дождя V_t = 36,34·(0,001·ρ₀q_r)^0,1364·√(ρ₀(0)/ρ₀) м/с на каждом узле;
  дождь уходит в землю, сумма осадков копится по столбцам (мм).
- Испарение дождя по Klemp–Wilhelmson ∝ (1 − q/q_s)·C·(ρ₀q_r)^0,525, не дальше насыщения;
  охлаждение от него пишется и в θ, и в индикатор cold pool.
- Льда нет. Снег на экране — визуализация частиц осадков по высоте уровня 0 °C.

### Поверхность и солнце

Инсоляция — «солнце в зените» × косинус зенитного угла (день равноденствия, учитывается
широта; восход 6:00, закат 18:00). Баланс энергии поверхности
`src/core/surface.ts`: поглощённое = длинноволновые потери (90 Вт/м²) + запас в почве/воде +
H + LE. Доля испарения — «мокрая» доля поверхности × доступность влаги (тип поверхности,
влажность почвы). H и LE целиком уходят в два нижних уровня (профиль exp(−z/300 м)):
Δθ = H/(ρc_pΠh), Δq = LE/(ρL_vh). Ночного выхолаживания нет.

### Диагностика

- Частица поднимается по давлению среды: сухая адиабата (сохранение θ) до LCL, псевдовлажная
  адиабата dT/dp выше, шаг 25 м. Совпадает с MetPy 1.7.1: CAPE ±1,1 %, CIN ±2 Дж/кг.
- Зондирование частицы от поверхности (в приложении: +0,5 K и вовлечение; для тестов есть
  «чистая» частица), CAPE, CIN, LCL, LFC, EL, точка росы, уровень 0 °C.
- Годограф 0–10 км и сдвиг ветра 0–6 км.
- Спиральность восходящего потока UH = ∫ w·ζ dz по слою 2–5 км (по столбцам). Пороги
  откалиброваны под эту сетку: «вращение» ≥ 100 м²/с², «мезоциклон» ≥ 150 м²/с²
  и держится ≥ 10 мин (в 3-км оперативных моделях обычно ~75).
- Число восходящих ядер (связные по горизонтали столбцы, где на ~2–6,5 км есть w > 2 м/с с облаком)
  и классификация режима: одиночная ячейка, мультиячейка, наклонённая ячейка,
  суперячейка с мезоциклоном, преобладание оттока.

## Проверка

`npm test` запускает ядро в Node (vitest). Известные ошибки помечены `it.fails`: такой тест
обязан падать, и когда исправление заработает, vitest сообщит об этом — пометку снимают.

- **Инварианты** ([`invariants.test.ts`](src/core/invariants.test.ts)): фон без триггера
  за 3 ч (θ, ветер, q_v); баланс воды в грозе за 1 ч с учётом выпавшего дождя; проекция
  убирает однородный w и не оставляет дивергенции после шага в грозе.
- **Сверка с MetPy 1.7.1** ([`sounding.test.ts`](src/core/sounding.test.ts)): CAPE, CIN,
  LCL, LFC, EL поверхностной частицы на трёх профилях; эталоны записаны в тест,
  пересчёт — [`tests/reference/metpy_parcel.py`](tests/reference/metpy_parcel.py).
- **Решатель давления** ([`pressure.test.ts`](src/core/pressure.test.ts)): случайное поле
  на шести сетках, включая чётные размеры с «шахматной» модой.

## Для программистов

### Устройство

| Путь | Что внутри |
|---|---|
| `src/core/` | расчётное ядро без Three.js и DOM: сетка, базовое состояние, модель, решатель давления, зондирование, солнце, поля для слоёв |
| `src/render/` | сцена Three.js: объёмные облака (raymarching по 3D-текстуре), срезы и объём полей, тени облаков на земле, частицы потоков и осадков, шейдеры |
| `src/simulation.worker.ts`, `src/simulation.ts` | расчёт в Web Worker и протокол сообщений: время, изменения настроек, термики → снимки полей в переиспользуемых буферах |
| `src/atmosphere.ts` | связка расчёта и сцены; держит «зеркальную» модель, в которую копируются снимки; единственная точка, через которую работает интерфейс |
| `src/describe.ts` | тексты о режиме грозы |
| `src/main.ts` | интерфейс, панели, сценарии, аэрологическая диаграмма и годограф |

### Ядро без браузера

```ts
import { AtmosphereModel, createGrid } from './src/core'

const model = new AtmosphereModel(config, createGrid({ nx: 40, ny: 32, nz: 30, width: 48_000, depth: 36_000, height: 18_900 }))
for (let s = 0; s < 3600; s++) { model.step(1); model.time += 1 }
console.log(model.rotation.uh, model.diagnostics().updraft, model.precipitation)
```

Модель детерминирована при заданном `config.seed`. Скорость — около 17 мс на шаг
на сетке по умолчанию (Node 24, один поток), из них ~7 мс проекция.

## Как пользоваться

Камера: ЛКМ — вращение, ПКМ — сдвиг, колесо — масштаб. Двойной клик по земле — тёплый
влажный пузырь. Изменение профилей перезапускает опыт; кнопки «Сценарии» выставляют
готовую погоду. Вкладки над сценой показывают поля (вертикальная скорость, отклонение
температуры, влажность, завихренность, UH, cold pool) срезами и объёмом; «Потоки» —
частицы по ветру; «Снег и дождь» — частицы осадков.

| Сценарий | Замысел | Поведение на текущей физике (60 мин) |
|---|---|---|
| Летний день | исходные настройки | суперячейка, мезоциклон с ~26-й минуты (CAPE 4,9 кДж/кг) |
| Мощная гроза | жара и влажный нижний слой | суперячейка, мезоциклон с ~24-й минуты, расщепление |
| Сухой воздух | сухой средний слой душит конвекцию | конвекция всё же развивается: CAPE остаётся очень большой |
| Сдвиг ветра | наклон облака сильным ветром наверху | поздние наклонённые ячейки |
| Суперячейка | изогнутый годограф, CAPE 3,6 кДж/кг | **сейчас не развивается** — перенастройка после блока микрофизики |
| Микропорыв | сухой подоблачный слой | порывы у земли до ~50 м/с |
| Жаркий город | сильный нагрев поверхности | мезоциклон с ~28-й минуты |

Старые сценарии сознательно оставлены с экстремальной CAPE (5–9 кДж/кг).

## Журнал изменений

### 2.0 (в работе)

- **29.09.2026 — дождь снова доходит до земли; карта суммы осадков.** После перехода на
  схему Кесслера скорость падения бралась в точке прибытия, а под дождевым столбом она
  нулевая — дождь опускался только с нисходящими потоками (баланс воды при этом сходился,
  поэтому тесты молчали). Теперь узел берёт скорость падения дождя над ним; тест требует
  осадков на земле. Кнопка «Сумма осадков» рисует выпавший дождь на земле, интенсивность —
  поток ρ·q_r·V_t у земли в мм/ч (раньше q_r·12000 по максимуму во всём объёме).
- **29.09.2026 — индексы суперячейки:** движение по Банкерсу (точки RM и LM на годографе),
  SRH 0–1 и 0–3 км, SCP и STP в панели (`stormIndices`, `src/core/kinematics.ts`); совпадают
  с MetPy (движение ±0,05 м/с, SRH ±1 м²/с², SCP и STP ±3 %).
- **29.09.2026 — узлы ветра на 0,5 и 1 км.** Годограф в нижних 3 км больше не одна прямая:
  изгиб в нижнем километре (признак смерчеопасной среды, большая SRH 0–1 км) задаётся
  ползунками. У сценариев без этих узлов профиль прежний.
- **29.09.2026 — верх модели на 18,9 км** (30 уровней, шаг по высоте прежний), губка с 14 км:
  вершины сильных гроз и перебросы через тропопаузу больше не упираются в поглощающий слой.
  Шаг расчёта примерно на 25 % дольше.
- **29.09.2026 — стандартные индексы частицы:** MLCAPE/MLCIN (перемешанный слой 100 гПа),
  MUCAPE (самая неустойчивая частица в нижних 300 гПа) и DCAPE (энергия нисходящего потока)
  в панели и в ядре (`parcelIndices`); совпадают с MetPy 1.7.1 (DCAPE ±0,3 %, MLCAPE ±3 %).
  CAPE приложения (+0,5 K, вовлечение) остаётся отдельной величиной.
- **29.09.2026 — режимы отображения слоёв:** «срезы + объём сильных отклонений», «только
  срезы», «только объём» — всё поле с настраиваемыми порогом прозрачности и плотностью.
- **29.09.2026 — счётчик срабатываний ограничителей скорости** (|u|, |v| ≤ 85, |w| ≤ 60 м/с)
  в панели состояния: не ноль — модель вышла из рабочего диапазона.
- **29.09.2026 — каждый запуск уникален.** Ползунок «Seed» убран: старт, перезапуск и выбор
  сценария берут новый случайный сид. Он хранится в адресе страницы (`?seed=…`), так что
  понравившийся первый запуск можно повторить по ссылке.
- **29.09.2026 — расчёт в Web Worker.** Физика идёт в отдельном потоке, интерфейс и сцена
  больше не ждут шагов модели. Хвост невыполненных шагов ограничен 12 шагами: после
  тормозящих кадров модель не «догоняет» минутами.
- **29.09.2026 — неупругое (anelastic) приближение.** Проекция делает бездивергентным поток
  массы ρ₀**u**, а не скорость: поднимающийся воздух расширяется, как в реальной атмосфере.
  Решатель остался точным (ДПФ + прогонка, веса ρ₀ в коэффициентах), вода сохраняется
  в массовых единицах. Уровень 1 плана закрыт, кроме калибровочного теста WK.
- **29.09.2026 — баланс энергии поверхности.** Инсоляция через косинус зенитного угла
  (зависит от широты), H + LE + запас + длинноволновые потери = поглощённому. Нагрев у земли
  в полдень ~200 Вт/м² вместо ~430, испарение в ~8 раз сильнее (раньше соотношение Боуэна
  было искажено). Ползунок «Солнце в зените», по умолчанию 1000 Вт/м².
- **29.09.2026 — калибровочный тест Weisman–Klemp.** Идеализированные среды задаются
  формулами (`EnvironmentProfile`, `weismanKlemp()`). Классическая суперячейка WK на
  нашей сетке пока не расщепляется и гибнет к 40-й минуте — тест помечен как известное
  отставание и станет приёмочным для улучшения переноса (уровень 2).
- **29.09.2026 — «Суперячейка» перенастроена под новую физику.** Теплее и влажнее
  (31 °C, 78 %), сильнее ветер (8/16/24/30 м/с) при том же повороте 140° → 255°:
  одна ячейка с мезоциклоном с 24-й по ~55-ю минуту, UH до 550 м²/с², вращение
  преимущественно циклоническое.
- **29.09.2026 — честное испарение, ползунки-подгонки удалены.** Охлаждение при испарении
  дождя — ровно L/c_p на испарённую массу. Ползунки «Вовлечение сухого воздуха»,
  «Эффективность осадков», «Испарение осадков», «Сила cold pool» удалены: микрофизика только
  физическая. «Микропорыв» без множителей даёт порыв ~7 м/с вместо 25 (переработка
  сценариев — уровень 2).
- **28.09.2026 — схема Кесслера.** Автоконверсия в 35 раз медленнее (как у Кесслера),
  добавлена аккреция, испарение дождя по Klemp–Wilhelmson, скорость падения зависит от
  количества дождя и плотности воздуха. Дождь начинается позже, холодный купол слабее,
  грозы живут дольше.
- **28.09.2026 — насыщающая коррекция.** Пар и облачная вода после каждого шага в точном
  равновесии (было: 32 % избытка в секунду, а испарение облака зависело от ползунка
  «вовлечение»). Модуль `src/core/microphysics.ts`.
- **28.09.2026 — плавучесть без подгонки.** B = g·[(θ_v − θ_v,env)/θ_v,env − q_c − q_r]: облачная
